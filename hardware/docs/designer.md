# Hardware designer tool

What the tool in `hardware/` is for and how its files fit together. Setup and run steps are in [../README.md](../README.md).

## What it does
A local Vite app plus a Fastify API (127.0.0.1:3101) that renders tscircuit board designs, prices the BOM from jlcsearch, and exports a JLCPCB zip (Gerbers, drill, `bom.csv`, `cpl.csv`). It is a design tool only: nothing here runs on the ESP and no firmware, Node-RED or Manager code reads it.

## Layout
- `designs/<board>/index.tsx` + `board.json`: one board per folder. `board.json` carries name, description, revision and notes; put open electrical doubts in `notes`.
- `lib/*.tsx`: shared circuit blocks (`expansion-header`, `id-eeprom`, `relay-channel`, `srd-relay`, `screw-terminal`). Designs import them as `../../lib/<block>`. Change a block and every design using it changes.
- `app/` is the UI, `api/` the server (`bom.ts`, `build.ts`, `parts.ts`, `git.ts`).
- `docs/<feature>.md`: one hardware doc per firmware feature, same names as [docs/features](../../docs/features/), indexed in [docs/FEATURES_README.md](../../docs/FEATURES_README.md).

## When a design or block changes
1. For every feature the change affects, edit `hardware/docs/<feature>.md`: **Provided today** names the block or design, **Electrical limits** the numbers, **Gaps** what is still missing. Read the part from the design source, not from memory.
2. A new board that adds a bus, address, connector or pin use gets a line in each feature doc it touches (for example an I2C device in [bme280](bme280.md) or [modules](modules.md)).
3. If the board needs firmware support that does not exist (a module type, an EEPROM record format, a board profile), say so under **Gaps** in the hardware doc and in the firmware doc; if it is a real mismatch, add a line to [docs/lockstep-issues.md](../../docs/lockstep-issues.md).
4. Keep planned-but-undesigned things under **Gaps**, marked as planned. Do not describe them as provided.
5. Run `node tools/precheck.mjs`; it fails if a feature has no hardware doc.

## Builds that don't block you
- **Worker process per build.** `api/build.ts` forks `api/build-worker.ts` for every build, so a slow design never blocks the API or other designs. Builds are still serialized per design; a build that carries unsaved editor files is *supersedable*: a newer editor build kills it instead of queueing behind it.
- **Quick vs full.** `POST /api/designs/:name/build {files?, mode: "quick"|"full"}` (default `full`; BOM and export always use `full`). Quick rewrites `<board ...>` to `routeRemaining={false}` in memory (nothing is saved) and sets the tscircuit platform option `schematicDisabled` (schematic trace routing dominated big boards), so you get placement + ratsnest without autorouting and the Schematic tab is empty; unrouted-net errors become warnings. The debounced edit build and the **Build** button are quick; **Route** is the full autorouted build.
- **Progress and Cancel.** `GET /api/designs/:name/build/status` returns `{state, mode, phase, progress?, elapsedMs}` (the app polls it every 0.5 s and shows phase, a bar, an elapsed timer and **Cancel** in the toolbar). `POST /api/designs/:name/build/cancel` kills the worker.
- **Disk cache.** The last good build per design is stored in `hardware/.cache/builds/<name>.json` (gitignored) with the hash of its inputs. `GET /api/designs/:name/build/cached` returns it; opening a design shows it immediately while the rebuild runs, and an unchanged input hash returns the cache with `cached: true` (a full result also satisfies a quick request).
- **Ports.** `HW_API_PORT` / `HW_APP_PORT` override 3101 / 5173.
- **Open:** router choice, re-route selected nets and keep-existing-traces are not exposed; tscircuit only offers them via `<autoroutingphase>` / `autorouter` board props in the design source, not as a runtime option.
- **Quick-mode limits.** The `routeRemaining` rewrite is a regex over every `.tsx` file (design and `lib/`, including comments), and it adds `routeRemaining={false}` to every `<board`. Explicit `<autoroutingphase>` elements and `<trace>`s still route in quick mode. The BOM tab uses quick builds; export uses full.
- **Supersede rules.** A quick editor build is killed (or skipped if queued) by any newer editor build; a Route (full) build is only replaced by a newer Route, so typing does not kill a long route. Workers exit if the API process goes away.
## Click on the board, not the code
- **PCB tab** is an interactive view drawn from the circuit JSON (`app/src/PcbEdit.tsx`, model in `pcbModel.ts`); the stock tscircuit viewer stays on the **PCB (viewer)** tab. Click a part to select it, drag to move (snap 0.1/0.25/0.5/1 mm or off, remembered), arrow keys nudge, **R** rotates 90° (Shift+R back), Esc clears. Click a pad or trace to highlight its net in the PCB and the Schematic (click a schematic wire or part too); the side panel lists the pins on the net.
- **Properties panel** (right of the preview): name, value (resistance/capacitance/...), footprint, LCSC part, X/Y, rotation. Edits rewrite the JSX in memory (the Save button then writes it, the preview rebuilds). Parts made by a `lib/` block or a `.map()` loop, and props that are expressions, are read-only with a note saying why.
- **Code** button in the toolbar shows/hides the editor (hidden by default, remembered in localStorage `hw.codeOpen`).
- **Source rewrite module** `api/source-edit.ts` (TypeScript compiler AST, edits spliced into the original text so formatting is kept; a rename also updates `.NAME` selectors in strings). API, also for Claude:
  - `GET /api/designs/:name/components/source` lists elements with a literal `name` (their literal props, which props are expressions, whether they sit in a loop, line number). `POST` (same path) takes `{ files }` to include unsaved edits.
  - `PATCH /api/designs/:name/components/:component` with `{ props: { pcbX: 1.5, pcbRotation: 90, resistance: "10k", footprint: "0603", lcsc: "C123", schX: null } }` (`null` removes a prop; add `delta: { pcbX: 0.5, pcbRotation: 90 }` to move numeric literals relative to the current text, which is what the UI uses so rapid nudges never act on stale values; the response carries `warnings`, e.g. references left after a rename; `lcsc` maps to `supplierPartNumbers={{ jlcpcb: [...] }}`). Without `files` it writes the design file on disk; with `files` it only returns the patched text `{ file, content, written }`.
## Parts palette (left sidebar)
Lists the `lib/` blocks (parsed from each file's exported component, its `…Props` type and doc comment) plus primitives (resistor, capacitor, LED, diode, pin header, chip, mounting hole). Click an item, or drag it onto the preview, to open a small form: `name` is auto-generated and unique (R1, C2, TB3…), defaults are filled, optional props sit under **Advanced**. **Add to board** inserts the JSX before `</board>` (and the `lib/` import) in the editor buffer; it is unsaved until Save, like any edit. The **JLC search** tab, and the search box on parts with an LCSC field, query jlcsearch (stock, price, Basic/Preferred/Extended, package); picking a result fills the LCSC number, and the footprint when the package is a plain standard one.

API (`api/palette.ts`), also usable by Claude:
- `GET /api/palette` – `{ lib, primitives }`, each item `{ id, label, tag, props[], … }` (`id` like `lib:SrdRelay`, `prim:resistor`).
- `GET /api/parts/search?q=…` – `[{ lcsc, mfr, package, stock, price, tier, footprint }]`.
- `POST /api/designs/:name/components` `{ item, props?, source? }` – without `source` it edits `designs/<name>/index.tsx` on disk; with `source` it writes nothing and returns the edited text (the UI uses this for its unsaved buffer). Returns `{ name, snippet, source }`; 422 on a bad prop or duplicate name.

Chips take `footprint="jlcpcb:<LCSC>"` when picked from search; the UI sends the last build's component names so generated names never collide. Placement: a blank position lands near the board centre, staggered so inserts do not stack; set `pcbX`/`pcbY` for exact placement. Open: placing at the pointer on drop (needs pcb-viewer coordinates), and "save selection as block".

## Connecting pins and the GPIO map (no typing net names)
Bottom panel tabs **Nets & connect** and **GPIO map**. Source: `api/connect.ts` (edits), `api/connect-routes.ts` (endpoints), `shared/nets.ts` (nets from circuit JSON, used by app and API), `app/src/Connect.tsx`, `app/src/Gpio.tsx`.
- **Connect mode**: switch it on (the preview jumps to the schematic), click pin A then pin B (a third click restarts), choose a net from the dropdown (default: join the net a pin is already on, else a suggested new name such as `U1_A0`) and press Connect. *Advanced* has pin pickers (also the way to pick pins on the PCB view, which cannot be clicked) and a custom net name. The edit lands in the editor as an unsaved change; Save writes it.
- **Nets list**: every net with pin count and the parts on it. Click to highlight its parts in the schematic and list its pins; Rename changes every `"net.X"` literal in all of the design's files. It is refused (with the file list) if a lib block also uses that net (for example `SDA`, `V3_3`), because it would split the net, and it asks before renaming onto a name that already exists (merging two nets; API: `merge:true`).
- **GPIO map** (designs using `Esp32S3Module`): every module pin with its net in a dropdown (existing nets, unconnected, or New net…). Pin list and default connections are read from `lib/esp32-s3-module.tsx`. Flags: a net on two IO pins, IO35–37 (octal PSRAM, error), strapping IO0/IO3/IO45/IO46, USB IO19/IO20, ADC2 (IO11–IO20) unusable with WiFi, JTAG IO39–42, UART0. The per-pin notes live in `pinNotes()` in `api/connect.ts` (WROOM-1-N16R8 specific); edit there if the module changes. It reads the source, so it needs no build.
- **How an edit is written**: for a pin the tool prefers, in order, the entry in the component's `connections={{…}}`, an existing `<trace from=".REF > .PIN" to=… />` (its `to` is retargeted, so no second net is created; if it was a pin-to-pin trace the old partner pin is put on the new net with an extra trace so it stays connected), then adds `connections` (lowercase primitives) or a new `<trace>` before `</board>` (lib blocks, which may not accept `connections`).
- **API (for Claude)**, all under `/api/designs/:name/`, JSON bodies. Edit endpoints return `{ ok, changed, how, source, written }`; without `source` in the body they edit `index.tsx` on disk, with `source` they only return the edited text (the app does this to keep unsaved edits).
  - `POST connect` `{ a:{ref,pin}, b?:{ref,pin}, net? }` puts `a` (and `b`) on `net` (`"SDA"` or `"net.SDA"`; omitted = suggested name). `ref` is the part's `name`, `pin` its port label as in the circuit JSON.
  - `POST nets` `{ circuitJson? }` lists nets with `pinCount` and `pins` (`GET nets` is the inspect endpoint: nets with kind and ports).
  - `POST rename-net` `{ from, to, merge? }` (response also carries `files`, every changed design file).
  - `GET|POST gpio` returns the map (`rows`, `clashes`, `nets`); `POST gpio/assign` `{ pin, net|null }` sets or clears an IO.
## Iterate safely (undo, autosave, snapshots, variants, diff)
- **Undo/redo**: `app/src/useHistory.ts` keeps a stack of whole file maps per open design. Every edit source calls `history.push(update, {key})` (the code editor does; a property panel or API-driven edit should too). Same-`key` edits within 1 s merge into one step. Ctrl+Z / Ctrl+Shift+Z (or Ctrl+Y) work outside the code editor, which keeps its own undo; toolbar buttons do the same. Snapshot restore goes through the stack, so it is undoable.
- **Autosave**: toggle in the toolbar (default on, remembered in localStorage). Saves 1.5 s after the last change and when you leave the design. The toolbar reads Saving / Unsaved changes / Saved from the real difference between editor and disk. Ctrl+S still works.
- **Snapshots** live in `hardware/.cache/snapshots/<design>/<id>.json` (gitignored). Not in `designs/<name>/.snapshots`: the build walks every `.ts/.tsx/.json` under the design folder and would treat snapshots as design files and show them in `git status`. Restore first stores the current disk state as an automatic snapshot, so it is never destructive. Snapshots are not a substitute for git commits.
- **New variant**: button on each design card and in the workspace. Copies the whole folder to `<base>-revb`, `-revc`... and sets `board.json` `revision` to the same letter (next after the source's, skipping taken names).
- **Revision diff**: "Snapshots & diff" tab. Pick two snapshots or one vs current (unsaved editor state included). Builds both revisions, matches parts by name, lists added / removed / moved / changed (value or footprint props, position, rotation, layer, board size). The preview pane switches to a board map with the same colours; click a row or a part to focus it. It is a separate SVG built from circuit-json geometry, not drawn inside the tscircuit PCB viewer (its pan/zoom is not exposed). Diffs build two full revisions, so they are slow on boards that autoroute slowly.

### API (for Claude and scripts)
```
GET    /api/designs/:name/snapshots                  list, newest first
POST   /api/designs/:name/snapshots   {label?, files?}  files omitted = files on disk
GET    /api/designs/:name/snapshots/:id              full snapshot with files
DELETE /api/designs/:name/snapshots/:id
POST   /api/designs/:name/snapshots/:id/restore      writes files to disk, returns {files, backup}
POST   /api/designs/:name/variant     {name?}        returns {name, revision}
POST   /api/designs/:name/diff        {a, b, files?}  a/b = snapshot id or "current"; files = unsaved state for "current"
```
Known limit: a build with override files still merges the files on disk, so diffing a snapshot that lacks a file that exists on disk sees that file.
## Checks that explain themselves
After every build the API runs design-rule checks and returns them in the build response (`checks`) and from `GET /api/designs/:name/checks` (full list, plus `checklist` and `notes`). Each issue has `severity` (`error`/`warning`/`info`), `title`, `message`, `why` (why it matters), `fix`, `refs` (parts/nets) and `where` (`view`, `x`, `y`, `w`, `h` in mm, `pcbComponentId`) so Claude can act on them.
- Sources: the build's own errors/warnings, `@tscircuit/checks` `runAllChecks` (clearance limits taken from `rules`), and custom rules in `api/checks.ts`: trace width vs current on nets listed in `rules.netCurrents` (IPC-2221, 10 °C rise), traces thinner than `rules.minTrace`, copper pour or traces under the ESP32 module antenna end (a 15 mm outward / 6 mm inward zone at the pad-free edge of any component named or numbered `esp32`), and ICs whose supply pin has no ground capacitor within `rules.decouplingMaxDistance`. Schematic tidiness and pin-role hints are `info` and hidden behind a toggle.
- **Problems tab:** click an item (or **Show**) to switch to the PCB, pan and zoom to it and draw a marker; **Why?** expands the explanation and fix. Zoom works by reading the viewer's transform from its focus outline and driving it with synthetic drag/wheel events (the viewer has no camera API), so a big viewer upgrade may need that revisited. Schematic issues only switch the tab.
- **Review tab:** `board.json` `checklist: [{id, text, status: "open"|"ok"|"wontfix", note}]`; tick status, add notes and items. **Split notes into checklist** turns the numbered `(1) … (2) …` items of `notes` into entries (idempotent; `notes` is kept). **Advanced: design rules** edits `board.json` `rules: { minTrace, minClearance, copperOz, netCurrents: {"VLOAD": 20}, decouplingMaxDistance }` (mm, mm, oz, amps, mm).
- `PATCH /api/designs/:name/meta` with `{checklist?, rules?, notes?, splitNotes?}` edits `board.json` on disk, keeping other keys. `board.json` is excluded from the build hash unless a source file mentions it, so ticking items does not rebuild.
## Cost and ordering
- **Cost chip** (toolbar, always visible): estimated cost per board at the BOM quantity = parts + JLC extended-part fees (from jlcsearch) + a rough PCB fab and assembly estimate. Hover for the breakdown; click opens the BOM tab. The fab/assembly part is labelled *est.*: it is a simple list-price model in `api/cost.ts` (`ESTIMATE`: per-cm² fab rate and minimum by layer count, $8 assembly setup + $1.50 stencil, per-joint and per-placement fees). Shipping, tax and promos are excluded; tune the constants when JLCPCB prices change.
- **Swap to Basic** (BOM tab): for each Extended (not Basic/Preferred) resistor, capacitor, LED or diode, jlcsearch is queried for a Basic/Preferred part with the same package and value (capacitors also keep voltage and dielectric, resistors keep tolerance at least as tight, LEDs keep colour). Savings include the $3 extended fee. **Swap** rewrites the LCSC number in the design's own files (the editor picks up the change, rebuild follows). If the number lives in a `lib/` block it is only reported ("change it in lib/x.tsx"), because that would change every design using the block. Chips, connectors, transistors and relays are not matched automatically.
- **Export panel**: Export opens a pre-flight (layers, size, part count, missing LCSC numbers, build errors/warnings, estimated total) and a CPL preview: every part on the board outline with its pads, pin-1 pad in red and a line along the `cpl.csv` rotation (0° points right; hover for the CPL row). JLCPCB's own part library can apply extra rotation offsets, so still check the placement preview on their site. Then it downloads the zip and links the JLCPCB quote page.
- **API for Claude** (all take the saved files; `qty` defaults to 10):
  - `GET /api/designs/:name/cost?qty=` – parts, extended fees, fab and assembly estimate, per-board and total.
  - `GET /api/designs/:name/swaps?qty=` – `{swaps:[{from,to,refs,savingTotal,canApply,hint,…}], skipped:[…]}`.
  - `POST /api/designs/:name/swaps/apply` body `{from,to}` – rewrites the LCSC number; returns changed files and any `libFiles` still holding it.
  - `GET /api/designs/:name/preflight` – checks plus the `cpl` array (ref, x, y, rotation, layer, pads).
## Explain and Describe a change
The bottom panel has an **Explain** tab (a generated, grouped walkthrough of the saved build; click a sentence to highlight its parts on the PCB) and a **Describe a change** tab (type a request, it is stored as pending; Claude answers through the API with a proposal, you review the diff and Accept or Reject). The same data is available to Claude through a stdio MCP server (`hardware/mcp/server.ts`, registered in the root `.mcp.json`). Endpoints and tools: [api.md](api.md). `HW_API_PORT` / `HW_APP_PORT` change the ports when several copies run.
## New designs, shortcuts, design list
- **New-design wizard** (`+ New design`): name, template (Blank, Expansion card = `ExpansionHeader` + `IdEeprom`, Base controller = ESP32-S3 module + Buck3v3 power), size preset or custom W×H, 2/4 layers, mounting holes (none or 4× M3 3.2 mm, 4 mm in from the corners), description. Files are generated server-side from `api/templates/index.ts`, so Claude can do the same: `POST /api/designs` with `{ name, template?: "blank"|"expansion"|"base", width?, height?, layers?: 2|4, holes?: "none"|"m3-corners", description? }` (409 if the name exists). `GET /api/templates` lists templates and size presets. The Base template uses `lib/esp32-s3-module` + `lib/buck-3v3` with a 10k/1uF EN reset network and 10uF + 100nF next to the module 3V3 pin; the module antenna sits at the top edge and the bottom GND pour has a notch under it (`outline` polygon), so a new base board starts with no design-rule errors. Each template has a minimum size (larger with corner holes), enforced by the API (400) and the wizard.
- **Design list**: sorted by last modified; each card shows a cached PCB SVG (written after every successful build to `hardware/.cache/thumbs/`, served at `GET /api/designs/:name/thumb.svg`, placeholder until the first build), modified time, and Duplicate (`POST /api/designs/:name/duplicate`, optional `{to}`) and Delete (`DELETE /api/designs/:name`) buttons. Delete asks for confirmation and moves the folder to `hardware/.trash/<name>-<timestamp>/`; nothing is hard-deleted. `.trash/` and `.cache/` are git-ignored.
- **Shortcuts** (press `?` for the overlay): Ctrl/⌘+S save, Ctrl/⌘+Enter build (not inside the editor), `1`/`2`/`3` Schematic/PCB/3D, `J` toggle bottom panel, `E` focus the code editor, Esc leaves the editor. Single keys are ignored while typing.
- **Preview rebuilds**: the previous viewer stays mounted and the new one fades in over it (~0.45 s settle), so the preview no longer blanks. Pan/zoom is not kept across rebuilds because the viewers do not expose it; the new viewer starts at its default view.
