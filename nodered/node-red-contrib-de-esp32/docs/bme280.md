# BME280 (Node-RED)

Firmware: [docs/features/bme280.md](../../../docs/features/bme280.md) · Manager: [manager/docs/bme280.md](../../../manager/docs/bme280.md) · Hardware: [hardware/docs/bme280.md](../../../hardware/docs/bme280.md)

## What Node-RED does with it
The generic `de-esp32-module` node ([modules.md](modules.md)) with `modType` `bme280`. Picker shows "BME280 · I2C" (one button per `kind:"i2c"` bus in `/api/v1/hardware`; the board lists only `i2c0`).

## Node settings
| Node | Property | Maps to firmware field | Notes |
|---|---|---|---|
| `de-esp32-module` | `modType` | `type` = `bme280` | |
| | `bus` | `bus` | `i2c0` only in practice |
| | `pins.sda/scl` | `pins.sda/scl` | copied from the bus entry (21 / 22) |
| | — | `settings.*` | not sent; firmware defaults apply (`addr` 118, `sample_ms` 1000, oversampling 1, `filter` 0, `mode` normal) |

## Messages
`statusInfo()` detects an environment reading by `t_c`, `rh` or `p_hpa`:

```json
{"topic":"env0","payload":{"id":"env0","type":"bme280","ok":true,"addr":118,"t_c":22.53,"p_hpa":1013.25,"rh":45.1},"data":{...same...}}
```

Status: green `env0 · 22.53°C · 45.1% · 1013.25 hPa`, or `sensor error` when `ok:false`. With `ok:false` the firmware omits `t_c/p_hpa/rh`, so that state falls to the generic branch and shows "error". One message per firmware `io/env` event (on `ok` flip or movement ≥ 0.1 °C / 0.5 hPa / 0.5 %RH).

## Commands sent / events used
`module.add {type:"bme280", id, bus, pins}` on deploy (no `settings`). Listens to `io/env` frames on WS or MQTT `{prefix}/io`, matched by `data.id`.

## Code
- `nodes/de-esp32-module.js` — `statusInfo` (the `t_c`/`rh`/`p_hpa` branch).
- `nodes/de-esp32-module.html` — `applyChoice`, `wiring`.

## Gaps
- No settings UI: cannot pick `addr` 0x77, so a second BME280 on one bus fails (`i2c address must be unique on this bus`); no `sample_ms`, oversampling, filter or mode.
- The CS row (SPI-only) is still drawn for BME280. Clicking a CS button adds `pins.cs`; the firmware drops it, and on the next deploy `samePins` sees a difference and leaves the instance alone with "pins differ".
- The wiring hint says "tie RST high", which does not apply to a BME280.
- `busBusy()` does not check `sda`/`scl`, so a bus whose pins are in use by plain GPIO is not disabled; `module.add` then fails on the device.
