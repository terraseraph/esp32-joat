# BME280 (Manager)

Firmware: [docs/features/bme280.md](../../docs/features/bme280.md) · Node-RED: [nodered/.../docs/bme280.md](../../nodered/node-red-contrib-de-esp32/docs/bme280.md) · Hardware: [hardware/docs/bme280.md](../../hardware/docs/bme280.md)

## What the Manager does with it
Added, edited and removed through the generic Add-ons wizard ([modules.md](modules.md)), which renders the BME280 settings from `module.catalog`. Shown on the Add-ons card and as a BME280 tile on the Live tab.

## UI fields
| Screen | Field | Maps to firmware field | Notes |
|---|---|---|---|
| Add-on wizard · Pins | SDA / SCL | `pins.sda/scl` | pre-filled from bus pins (21 / 22) or a sibling sensor |
| · Pins | Bus | `bus` | only `i2c0` (hardware buses) |
| · Settings | I2C address | `settings.addr` | enum from catalog; clash check against other BME280s on the bus |
| · Settings | Sample period (ms) | `settings.sample_ms` | int, catalog `min`/`max` (firmware 200-10000) |
| · Settings | Temp / Pressure / Humidity oversampling | `settings.osrs_t/osrs_p/osrs_h` | enum |
| · Settings | IIR filter | `settings.filter` | enum |
| · Settings | Mode | `settings.mode` | `normal` / `forced` |
| Add-ons card | reading | `state.t_c`, `rh`, `p_hpa` | `22.5 °C`, `45 %RH · 1013 hPa`; `No sensor` when `ok:false` |
| Live tile (`BmeTile`) | °C, % humidity, hPa, address | `t_c`, `rh`, `p_hpa`, `addr` | `ok:false` → "No sensor", "Check SDA/SCL wiring (address 0x76)" |

Labels come from the catalog, so they read as the firmware's `kSettings` labels.

## Server side
Nothing BME280-specific. `Bme280State` in `server/src/types/device-api.ts` (`id`, `type:"bme280"`, `ok`, `addr`, `t_c?`, `p_hpa?`, `rh?`); WS topic `io/env`. Backups store `settings` as read from `module.list` (numbers) and send them back on restore.

## Fake device
`server/fake/commands.ts` `CATALOG` entry `bme280`; `installModuleState` sets a fixed reading `{ok:true, addr, t_c:22.5, p_hpa:1013.2, rh:45.1}` on add/configure (no periodic updates). Demo seed adds `env0` on i2c0 21/22. Differences from the firmware `kSettings`:

| Setting | Fake | Firmware |
|---|---|---|
| `def` / choice values | numbers | strings (`"118"`, `"1"`, `"normal"`) |
| `sample_ms` | 100-60000, label "Sample interval (ms)" | 200-10000, "Sample period (ms)" |
| `osrs_t/p/h` | values 0-5 = off, x1, x2, x4, x8, x16 (`ENUM_STEPS` uses the index) | values 1, 2, 4, 8, 16; no "off" |
| `filter` | values 0-4 = off, 2, 4, 8, 16 | values 0, 2, 4, 8, 16 |
| `delivery` | absent | catalog `delivery:"latest"` |

A fake-made backup with `osrs_t: 3` (x4 in the fake) would be refused by a real device (`settings.osrs_t invalid`); `filter: 1..4` likewise.

## Gaps
- String vs number settings (see [modules.md](modules.md) Gaps): new sensor's `sample_ms` fails validation until retyped; on Edit the saved `addr`, `osrs_*`, `filter` fail "Choose one of the listed values" until re-picked; the address clash check compares `118` to `"118"` and misses clashes.
- Editing the only BME280 on i2c0 reports SDA/SCL "in use (bus_i2c0)".
- No `i2c1`; no `delivery`.
